# Deployment

**Chosen: Render (web service, free) + Neon (Postgres, free).** No credit card,
GitHub-connected deploys, and the app can run its own migrations on boot.

Railway would be one step shorter but its free credit expires before the demo
window; Vercel/Netlify fight Express sessions and long-lived connections.

| Piece | Host | Plan |
|---|---|---|
| Express 5 app (`dist/server.js`) | Render | free web service |
| PostgreSQL 16 | Neon | free project |

`render.yaml` is committed, so Render can create everything from the blueprint.

## 1. Neon (database)

1. <https://console.neon.tech> → **New project** → region **Singapore**.
2. Copy the **pooled** connection string (the one with `-pooler` in the host).
   Append `?sslmode=require` if it isn't already there:
   `postgresql://USER:PASSWORD@ep-xxx-pooler.ap-southeast-1.aws.neon.tech/neondb?sslmode=require`
3. Nothing else to do — tables are created by the migration on first boot.

## 2. Render (app)

1. <https://dashboard.render.com> → **New → Blueprint** → pick this repo.
   Render reads `render.yaml` and asks for the `sync: false` values.
2. Fill in:
   | Variable | Value |
   |---|---|
   | `DATABASE_URL` | the Neon string from step 1 |
   | `DEMO_ADMIN_PASSWORD` | optional; defaults to `admin123` in the seed |
   | `DEMO_USER_PASSWORD` | optional; defaults to `user123` |
   `SESSION_SECRET` is generated by Render.
3. **Apply** — the first build runs `npm ci && npm run build`, then
   `npm run migrate && npm run seed && npm start`.

Without a blueprint, the equivalent manual service is:

```
Build command:   npm ci && npm run build
Start command:   npm run migrate && npm run seed && npm start
Health check:    /health
```

## 3. Verify

- `https://<service>.onrender.com/health` → `{"ok":true}`
- `/` renders (currently the scaffold page)
- `/preview/login`, `/preview/dashboard`, `/preview/admin` → the three design
  screens, no database needed
- Render logs show `migrate` finishing before `JobTrack http://localhost:…`

Migrations and seeds are **idempotent**, so every cold start re-runs them
safely: `migrate:latest` is a no-op once applied, seeds skip existing rows.

## Notes and limits

- **Free instances sleep** after 15 minutes idle; the next request takes
  ~30–60 s. Open the URL once before demoing, or hit `/health` on a timer.
- **Sessions live in memory** (`express-session` default). A restart or a sleep
  logs everyone out; fine for a demo, swap in `connect-pg-simple` if it matters.
- **Seed passwords are hashed once.** Setting `DEMO_*_PASSWORD` after the first
  seed does not rotate the stored hash — re-seed against an empty database.
- **Neon autosuspends** after 5 idle minutes and wakes in about a second, so the
  first query after a quiet period is slightly slower.
- `DATABASE_URL` wins over the `PG*` variables in `knexfile.js`, and takes the
  SSL branch (`rejectUnauthorized: false`) — required by Neon.

## Alternative: Railway

If a card is available and the credit is still valid:

```bash
railway init                     # link this repo
railway add --plugin postgresql  # provisions Postgres
railway variables set SESSION_SECRET=$(openssl rand -hex 32)
railway up                       # build + deploy
railway run npm run migrate && railway run npm run seed
```

Set the start command to `npm start` (migrations are a separate step there), and
copy `DATABASE_URL` from the Postgres plugin's connect panel.
